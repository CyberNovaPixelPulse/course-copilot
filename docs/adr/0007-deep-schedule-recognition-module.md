# 集中圖片到可編輯課程的辨識規則

設計已於 2026-10-26 完整確認，對應本機工程實作已加入；真實圖片驗收與正式切換尚未完成。課表辨識 module 直接交付可編輯課程，將模型回應處理、節次映射、課名整理、時段合併及辨識階段必要記錄收進 implementation，呼叫端不再依賴中間辨識資料與規則的先後順序。此選擇以集中規則取得 depth 與 locality，避免僅將原程式搬入另一個 shallow module。

帳號額度 module 繼續擁有辨識工作身分、額度保留、成功結果保存及扣次一致性；課表辨識 module 不另維護工作或額度狀態。辨識後沒有可用課程，或必要記錄失敗，不能回報成功，由帳號額度流程釋放保留。

本輪先保留模型、辨識提示與節次對照；相同模型回應的課程結果以維持現有行為為起點。發現誤合併、遺漏或其他問題時，以具體例子逐項確認行為修正，不在移動規則時默默更改結果。格式支援範圍、資料異常處理及合併細節尚待討論。

Q4–Q6 已確認：本輪限定目前五個等寬平日欄及既有數字、字母節次對照，不擴充週末、一般課表、圖片鐘點判讀或各校時間表。程式可偵測且無法安全整理的課程異常（如未知節次、非法星期、資料矛盾）使整次辨識失敗、不扣次，不得靜默刪除後以部分結果宣告成功；教室或教師未讀到可留空。此規則不能保證偵測模型所有漏讀。

同名課程可集中顯示，但每個上課時段須保留自己的教室，不同教室的時段不得直接合併；不推斷班級，也不補造圖片未提供的課號或教師。嚴格異常處理及教室保留為本輪明確同意的行為修正。

Q7–Q9 已確認：僅合併同一套節次表內連續且教室完全相同的同名課程時段；教室空白與已知教室不視為相同，移除單純依二十分鐘間隔跨表合併的判斷。離散節次保留分段。

同名課程同日的字母、數字節次若互相重疊，視為無法安全判定的矛盾，使整次辨識失敗且不扣次，不再自動以字母節次取代數字節次。互不重疊的跨表節次分別保留；不同課程的時間重疊仍保留供使用者檢查衝堂。

同名課程同時段出現不同的非空教室，視為無法判定的矛盾，不推斷班級也不任選教室，整次辨識失敗且不扣次。相同課名、節次與教室的完全重複資料去重；不同時間的不同教室正常保留。

Q10–Q12 已確認：檢查模型回應的五個星期欄是否完整、不重複，並檢查欄位、課程清單與節次資料前後一致；矛盾時整次失敗且不扣次，不自行移動星期位置。此檢查僅驗證回應內部一致性，不保證圖片判讀正確。

允許不改變含義的格式正規化，例如節次去除前後空白、字母大寫、數字前導零與課名多餘空白；不得猜測未知節次或把相似課名視為同一門課。未知或有歧義的內容依嚴格異常規則處理。

辨識 interface 回報穩定失敗分類與必要資訊，畫面呈現可採取行動的提示，區分課表內容異常、模型暫時故障與必要記錄失敗。不向使用者直接顯示原始模型回應或內部錯誤，也不自動發起第二次模型呼叫。

Q13–Q15 已確認：必要記錄區分模型呼叫完成與課表辨識成功，關聯既有辨識工作並記錄模型、可取得用量、耗時、整理結果與失敗分類；無法取得的用量標為未知，不記為零。本輪不額外保存原始圖片或完整模型回應。

主要測試 seam 是課表辨識 module 的同一 interface：正式模型 adapter 與固定回應測試 adapter 都經過相同的驗證、正規化、合併、衝突判斷與必要記錄流程。測試驗證最後課程或明確失敗結果，並保留帳號額度整合測試，確認失敗不扣次、成功可恢復。

確定性整理規則與真實圖片品質分開驗收。正式切換前需以人工標註的代表性圖片比較課程、星期、節次、教室及拒絕原因；素材及實際模型呼叫範圍另行確認。未完成圖片驗收前，不以固定回應測試宣稱辨識品質提升。


2026-10-27 後續授權：首張真實圖片驗收出現三個星期錯置及一個課名漏字後，使用者明確要求以 prompt-engineering-patterns 改善提示，因此本輪可調整原先暫時保留的辨識提示。僅加強既有五個平日欄的表頭／格線定位、逐字抄錄、通用示例及輸出前視覺核對；模型、取樣設定、schema、節次表、支援範圍及嚴格整理規則維持。此授權不包含新的付費模型呼叫；離線契約測試不能證明真實圖片品質改善，仍須依 #9 的素材與呼叫範圍確認進行驗收。
