# 集中付款返回與付款前課表恢復

設計討論中，Q1–Q15 已於 2026-10-26 確認。付款返回與恢復 module 擁有付款前準備、離站、返回參數解讀、確認等待、重新查詢與課表恢復提示；付款驗證及一次性權益發放仍由既有付款與帳號額度流程負責。本輪不更動價格、付款供應商或額度規則。

ECPay 與 Stripe 都須在前往付款前保存當下可編輯課表，包含手動修改；付款完成、取消返回或仍待確認時都應有恢復途徑。付款前課表不同於近期辨識工作保存的原始結果，其保存範圍與期限依以下決策處理。

返回後提示有付款前課表可恢復，由使用者明確選擇載入；若會取代目前課表，須先警告並取得確認。付款狀態可自動更新，但付款返回或延後確認不得自動覆寫課表。此選擇以明確恢復操作換取保護使用者當前編輯內容。

Q4–Q6 確認：付款前課表限定同一瀏覽器保存，支援重新整理、另開分頁與關閉後重開，並依登入帳號隔離；不同帳號不得查看或載入彼此的課表。跨裝置仍使用既有近期辨識結果，不同步付款前的手動修改。

付款前課表自保存起保留 7 天；付款成功與恢復操作都不提前刪除，也不延長期限。使用者可明確捨棄，到期後停止提供恢復，畫面須標示保存與到期時間。

保存失敗時預設留在目前頁面並保留課表，說明原因並提供重試。使用者可明確選擇「不保存課表，繼續付款」，確認可能無法恢復後才離站，不得忽略保存失敗而直接前往付款。

Q7–Q9 確認：每次前往付款各自保存一份付款前課表，與該次付款關聯，後一次不得覆蓋前一次。付款返回時優先提示對應備份；一般重開網站時可查看所有尚未到期的備份，以保存時間及付款方式區分。付款待確認或已確認均不影響恢復資格。

返回時未登入須先登入；登入其他帳號時停止該筆付款確認與課表恢復，提示使用付款時的帳號。保留返回線索供正確帳號登入後接續，不顯示其他帳號的課表內容，也不轉移備份。既有無帳號歸屬的舊暫存課表不自動匯入。

兩種付款方式均最多自動等待約 30 秒，尚未確認時顯示「尚待確認」、提供重新查詢並提醒已付款者無須再次付款；查詢失敗顯示「暫時無法確認」並允許重試。取消返回只代表離開付款頁，不宣告交易失敗，仍可恢復課表與查詢。只有後端驗證成功才顯示付款成功，整個流程不得自動建立新付款。

Q10–Q12 確認：沒有課表時可直接付款，不建立空白備份；返回後正常確認付款與更新額度，僅實際保存課表時提供恢復提示。

已保存課表但建立付款失敗或未取得付款資料時，保留備份及目前課表，告知付款未能開始，不自動重試建立付款。使用者可明確再次操作；未取得付款資料的備份仍可恢復，標示「尚未取得付款資訊」，沿用原本七天期限。

備份損壞或格式無法讀取不得阻止付款確認；停止恢復該份備份並清楚說明，不載入部分內容，也不影響其他有效備份。若存在近期辨識結果，可由使用者另行選擇載入，並說明不包含付款前的手動修改。

Q13–Q15 確認：module 統一提供開始付款、處理返回、重新查詢、列出備份、恢復及捨棄操作，回報可供畫面呈現的狀態；付款方式差異、等待與備份關聯封裝於 module。畫面負責顯示、取得使用者確認及套用恢復課表；付款成功與額度仍以後端驗證結果為準。

同一頁面同時僅允許一個建立付款操作，同一筆付款的確認查詢避免重疊。重複處理返回網址不得建立新付款、重複提示恢復或自動載入課表。不同分頁可各自操作，權益不重複發放由既有後端機制保證。

驗收使用可控制的付款、儲存與時間替身，涵蓋兩種付款方式、保存失敗、帳號切換、逾時與重查、多份備份、到期、損壞，以及明確確認後才覆寫課表，並以瀏覽器驗證主要操作流程。實際金流另列人工驗收，須另行授權；本機測試通過不代表實際金流已驗收。
