# 集中瀏覽器帳號權益快照

設計討論中，Q1–Q15 已於 2026-10-26 確認。瀏覽器帳號權益顯示 module 集中管理帳號權益快照，讓導覽列與上傳區透過同一 interface 取得狀態，付款、辨識及優惠碼兌換的後端結果經過同一 seam 更新。以集中更新順序取得 locality 與 leverage，避免各呼叫端自行維護快照及事件協議；既有後端帳號額度 module 繼續擁有授予、扣次與匯出資格的最終依據。

操作回應包含後端確認權益時，立即更新共用快照，同頁各處一起更新，不等待額外查詢；操作完成前不自行加減額度。較早啟動、較晚返回的舊查詢不得覆蓋操作結果，後續合法的額度下降則應正常呈現。

更新失敗時，若原帳號已有成功快照，保留數值並標示「更新失敗，目前顯示上次確認結果」，提供重試；若尚未取得成功結果，顯示「暫時無法確認權益」，不得假裝為零或因此引導重新付款。切換帳號立即清除前一帳號顯示；實際辨識與匯出仍由後端驗證權益。

Q4–Q6 確認：快照僅保留於目前頁面記憶體，不額外寫入長期儲存；同頁共用，重整或重開時先顯示載入，再向後端取得目前帳號權益。既有付款前課表保存政策不變。

同一瀏覽器的分頁僅通知「權益可能有變」，接收者重新查詢自己目前登入帳號的權益，不跨分頁直接套用完整快照，也不把通知視為權益證明。因收到通知而完成的查詢不再次廣播，避免通知循環。

首次登入載入、切換帳號、頁面回到前景與手動重試觸發查詢，同頁同帳號重複查詢合併，不加入固定間隔輪詢。同頁付款、辨識及兌換若已有完整後端權益結果，直接套用；僅知可能變動而缺少完整結果時才補查詢。

Q7–Q9 確認：本輪不新增後端權益版本。以瀏覽器端更新次序使操作開始前啟動的舊查詢失效；同帳號多個可能改變權益的操作重疊時，標示更新中，待這批操作結束後補一次查詢收斂，不依較大餘額或回應抵達次序判定權益新舊。

同帳號查詢不重疊；若查詢期間收到新的權益變動通知，記錄尚有變動，待目前查詢結束後補查一次，多個通知合併為一次後續查詢。單純重複重試或前景事件共用正在進行的查詢。通知不得直接變更額度或觸發付款、辨識。

後端明確回覆未登入時，立即清除權益數字、顯示需要重新登入，並使該登入階段未完成的更新失效；重新登入後重新載入。此情境不沿用暫時網路故障時保留舊快照的政策，也不得當成零額度。

Q10–Q12 確認：module 對畫面明確提供免費剩餘額度、購買／兌換剩餘額度、總額度及匯出資格；舊回應相容形狀集中於接收處轉換，不讓畫面各自解讀。後端現有欄位可保留，匯出資格不因額度耗盡消失，亦不得將 paid 當成本次付款成功的證據。

本輪停用開發工具以舊憑證切換已付費、未付費、增加及清零額度的四項操作，保留幣別預覽。測試透過可控制 adapter 模擬權益，不將開發預覽混入正式帳號快照；獨立展示模式另行設計。

導覽列與上傳區共用快照狀態，導覽列以簡短更新中／更新失敗標示，上傳區呈現完整說明及重試入口。背景更新保留已知數字，首次載入不顯示假數字；更新不清除課表、不關閉編輯，一般查詢失敗不自動彈出付款提示。

Q13–Q15 確認：接收處先驗證及轉換完整權益回應，通過後一次更新快照。缺漏、非法數值或分項與總額矛盾時不部分更新、不補零，保留同帳號上次成功快照並標示失敗；無成功快照時顯示無法確認。其他帳號或已失效登入階段的回應直接忽略，不影響目前帳號。

module 統一擁有登入階段、查詢合併、操作重疊、舊回應失效、分頁通知與錯誤狀態。付款、辨識與兌換流程提供操作生命週期及後端結果；畫面透過同一 interface 取得快照及要求更新，移除各自的權益查詢、同步事件與特殊競爭防護。既有付款返回、辨識工作與後端帳號額度責任維持原位。

主要測試 seam 為 module 對外 interface，以可控制延遲、失敗及登入狀態的 adapter 驗證可觀察快照，涵蓋舊查詢晚回、重疊操作後收斂、查詢期間收到變動、登入失效、帳號切換、異常回應及更新失敗。瀏覽器同時驗證導覽列與上傳區在付款、辨識、兌換、跨分頁、前景刷新與重試時的一致性，並確認不覆寫課表。測試使用替身，不執行真實付款或模型呼叫。
