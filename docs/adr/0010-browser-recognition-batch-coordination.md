# 集中瀏覽器辨識批次協調

設計討論中，Q1–Q15 已於 2026-10-26 確認。瀏覽器辨識工作協調 module 擁有裁切後圖片的辨識批次、工作接續、送出與查詢、逐張狀態及舊畫面結果失效；裁切互動與圖片壓縮維持各自職責，透過 adapter 提供準備好的圖片，畫面負責呈現及取得確認。集中順序要求以取得 depth 與 locality；後端帳號額度 module 仍擁有辨識工作身分、額度保留與扣次一致性，課表辨識 module 仍擁有圖片到課程的整理規則。

新辨識期間保留目前課表，失敗不清除既有內容；結果準備好後另行處理載入與覆寫確認。等待期間若使用者編輯或恢復另一份課表，遲到結果不得直接覆寫。

同一批次逐張依序辨識，遇第一個失敗或尚待確認的工作便暫停後續送出。逐張列出成功、失敗／待確認與未送出狀態，保留成功結果供使用者選擇載入，不以整批失敗抹去已完成結果。扣次仍依每個工作的既有規則，不自動重送失敗圖片或啟動未送出圖片；單張資料矛盾整張失敗的嚴格辨識政策不變。

Q4–Q6 確認：成功結果先組成本批次的候選課表，由使用者明確按「載入本批次成功結果」才取代目前課表；已有內容時先警告並取得確認，不自動套用，也不自動與目前課表合併。部分成功亦可載入，但須明示尚缺的圖片；單張工作仍可由既有最近辨識恢復。

批次暫停後依逐張狀態提供不同操作：已確認失敗或逾期者，使用者明確重試這張才建立新工作，已成功圖片不重辨識；執行中或結果不明者先查詢原工作，不直接建立新工作。尚未送出者須由使用者按「繼續剩餘圖片」接續，也可明確略過失敗／待確認圖片後繼續其他圖片。暫停工作稍後確認成功，亦不自動啟動剩餘圖片。

任一圖片裁切或壓縮準備失敗時，先暫停自動送出，保留其他已準備圖片並指出失敗圖片。使用者可重試準備、明確略過或取消這批；略過後依確認的圖片清單繼續，不默默少送一張。準備失敗不建立辨識工作、不消耗額度。

Q7–Q9 確認：組合多張成功結果時，僅移除課名、教師、星期、起訖時間及教室完全相同的重複時段，其餘資料完整保留。不做相似課名比對、不猜班級、不跨圖片重合併連續時段；不同資料時間重疊時保留並提醒檢查，不改變單張圖片嚴格辨識規則。

同頁一次僅保留一個可操作辨識批次，送出、重試及繼續皆明確對應該批圖片。未處理完時新選取或拖入圖片不加入，提示先完成或結束目前批次；之後新批次不包含舊預覽圖片。結束批次僅停止後續協調，不宣稱取消伺服器工作或退款。

辨識期間允許載入範例、恢復及編輯目前課表；仍更新逐張狀態及候選結果，但不得改動目前課表。遲到結果須由使用者再次明確載入，帳號權益仍依後端結果更新。課表與批次進度分開管理，不用清空課表或丟棄整批回應處理衝突。

Q10–Q12 確認：批次圖片與操作進度僅保留於目前頁面，不新增圖片或整批資料的持久保存；送出前清楚說明。重整或關閉後，已成功工作仍按既有七天政策從最近辨識恢復，未送出圖片需重新選取，不保證恢復整批候選課表。重新選圖若存在同帳號待確認線索，先處理原工作，不直接建立新辨識。

送出後網路中斷或回應無法讀取時，自動查詢一次原工作：成功則取回結果，明確失敗／逾期則顯示對應狀態；執行中、查不到或查詢故障則保持尚待確認，暫停批次並提供重新查詢。查不到不代表失敗，不持續輪詢、不因結果不明自動重送或新建工作。

送出前須成功保存工作識別與待確認線索。保存失敗保留準備圖片、指出問題及提供重試，不提供略過保存仍辨識；該圖片尚未建立後端工作、不消耗額度，其他已成功結果及目前課表仍可用。

Q13–Q15 確認：待確認工作線索依帳號保存，自建立起保留七天，不因查詢延長。確認工作成功、失敗或逾期後結束其待確認用途；後續明確重試依既有規則建立新工作。過期或損壞先說明並提供最近辨識入口，須由使用者明確確認「以新工作重新辨識，成功會再扣一次」才開始新工作。可辨識工作身分的舊格式線索先查原工作，不因格式升級自動重辨識。

瀏覽器單張送出最多等待約九十秒，工作狀態查詢最多等待約十五秒。送出超時沿用一次原工作查詢，仍無法確定便標示尚待確認並暫停，保留線索及已完成結果。等待上限不代表取消伺服器工作，也不更動後端辨識期限、三分鐘額度保留或扣次規則，不自動建立新工作。

主要測試 seam 為新 module 對外 interface，使用可控制的送出、工作查詢、儲存及時間 adapter 驗證逐張狀態、候選結果、送出範圍及建立新工作的時機。瀏覽器驗證準備失敗、部分成功、明確載入及覆寫確認、重試／略過／繼續、重整後取回、帳號切換，以及編輯或恢復後遲到結果不覆寫課表。沿用既有權益同步測試，確認畫面操作不阻止後端結果更新額度；不執行真實模型或付款。

Q1–Q15 全部同意，這輪設計討論完成；尚未轉為規格、拆票或實作。
