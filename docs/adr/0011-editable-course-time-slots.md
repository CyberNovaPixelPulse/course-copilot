# 統一可編輯課程時段的語意與變更規則

Q1–Q15 已於 2026-10-26 確認；使用者隨後指示轉為規格，設計討論完成。規格已發布為 [GitHub Issue #32](https://github.com/CyberNovaPixelPulse/course-copilot/issues/32)，標記 ready-for-agent。核准的八張子票 #33–#40 已發布，皆標記 ready-for-agent，並驗證原生子 Issue 及阻擋關係；父規格本文與狀態不變。已依子票實作；本機驗收方式與外部驗證限制見課程時段驗收文件。

Q1：可編輯課程時段 module 集中處理時間解析、時段有效性與移動／調整時段的規則，供手動新增、週曆編輯、分享圖片、付款前課表恢復及 ICS 匯出共用。畫面仍擁有呈現與操作，辨識器仍擁有圖片節次到時間的轉換，既有辨識格式與範圍不變。此邊界避免各個入口自行接受、隱藏或修正同一筆資料。

Q2：有效時段限定同一天，起訖時間各在 00:00–23:59，精確到分鐘，且結束必須晚於開始。不支援跨日或 24:00；匯出不得自行把倒序時間推測為隔日。手動選項與拖曳步距另行決定，不得據此改寫既有有效資料，例如 07:10–08:00。

Q3：週曆預設顯示 08:00–22:00；有更早或更晚的有效課程時，向外擴展至能完整容納課程的整點邊界。顯示邊界不限制有效時段，也不截斷資料。分享圖片亦須完整容納有效課程，可依圖片尺寸採用不同的排版範圍。

Q4–Q6 已確認：手動新增與編輯皆提供週一至週日；週曆預設顯示週一至五，有週末課程才展開週末。圖片辨識維持既有五日範圍。

新增與編輯視窗皆提供開始、結束時間輸入，支援 00:00–23:59、每分鐘精度。輸入未完成或無效時指出原因，確認且驗證通過後才套用，取消保留原資料。既有課名、教師及教室的修改範圍維持原行為，時間修改只影響選中時段。

整段拖動以十五分鐘為位移步距，保留原本分鐘偏移與時長；碰到當日有效時間邊界時限制整段位移，不縮短課程。調整開始或結束端點時，僅選中端點以十五分鐘增量變動，另一端保持原值；最短時長一分鐘，不得零長度或倒序。超過拖曳門檻才改動時間，單純點擊開啟編輯不改時間；拖曳取消恢復原時段。精確微調由時間輸入提供。

Q7–Q9 已確認：載入資料若仍可辨認為課程及時段，保留無效時段的原值，列出課名、原始內容及無效原因，提供編輯修正與刪除該時段的入口。有效時段照常顯示及編輯；無效時段不放入時間格，不自動改值、推測跨日或刪除。連基本課程結構都無法辨認的資料，明確回報無法載入。

產生 ICS 或分享圖片前檢查整份課表；任一時段無效便阻擋整份產生並指出問題，直到使用者修正或明確刪除。前端與後端共用有效性規則，後端亦驗證傳入資料，避免繞過畫面而產生不同結果。

衝堂與時段有效性分開處理。不同課程或同一課程的重疊時段皆完整保留、並排顯示並提醒，仍可編輯及輸出，不自動移動、合併或刪除。前一時段結束與下一時段開始相同不算衝堂。既有圖片辨識及批次組合的嚴格檢查、去重規則不變。

Q10–Q12 已確認：付款前課表區分可安全保存／恢復的課程結構與可供輸出的有效時段。結構可辨認者完整保存，包括待修正時段；恢復後列出問題，修正前阻擋輸出。帳號隔離、自建立起七天期限、明確選擇恢復及覆寫確認沿用既有決策，不因恢復延長期限。

一次拖曳期間固定當下時間軸與顯示範圍，放開後才重新計算。拖曳可到達的時間限制在當下可見範圍及當日有效時間內，整段移動保留時長；移到可見範圍外由精確時間輸入提供，確認後週曆自動擴展。顯示上界可標示 24:00，但僅為時間軸邊界，課程時間不得填入 24:00。

時間輸入接受一位或兩位小時、兩位分鐘及前後空白，驗證通過後統一為 HH:mm。其他格式指出錯誤，不猜測、不進位、不吸附到十五分鐘。既有資料可如此明確整理者視為有效；不能整理的原值保留於修正入口。

Q13–Q15 已確認：有多個時段時提供「刪除這個時段」；只剩一個時段時改為「刪除這門課」，取得確認後移除整門課。既有資料若有無時段課程，列入待修正清單，提供補上時段或明確刪除，不能默默略過。空課表明確提示尚無可輸出的課程。

分享圖片保留週課表版面並完整涵蓋有效時段；格內放不下課名與起訖時間時，以編號對應圖片下方明細，列出課名、星期及時間，必要時增加圖片高度。不為固定尺寸而隱藏課程或加長課程時間。

主要測試邊界為共用時段介面，搭配瀏覽器驗證完整流程。規則測試涵蓋時間格式整理、無效時間、同日限制、一分鐘時段、週末及首尾相接不算衝堂；移動保留原始分鐘偏移與時長、碰邊不縮短、單擊不改值、取消恢復及端點調整。瀏覽器涵蓋新增早晚課與週末課、精確編輯、無效資料修復、刪除最後時段、付款前保存及恢復。輸出驗證涵蓋無效資料阻擋 ICS 與分享圖片、有效早晚課／短課／衝堂課完整輸出、後端拒絕無效時段。沿用既有辨識、批次、權益及付款恢復回歸檢查；使用受控資料，不執行真實模型、付款或部署。
