# 行事曆輸出與交付協調

來源：GitHub #41，子票 #42–#48；ADR 0012。

`createCalendarExport(accountId, dependencies)` 是匯出的主要行為邊界，畫面透過啟動／明確替換、重試準備、交付、圖片重試、關閉／重開結果與生命週期操作協調。訂閱狀態包含固定快照、準備階段、已準備 ICS、交付進度與問題，以及獨立圖片狀態。畫面不再自行掌握請求、快照及重試順序。

- 新操作複製並驗證課表；等待期間的編輯不改變已送快照。準備中重複點擊不送請求，已準備後一般點擊只重開同次結果；明確改用目前課表才取新快照。
- 操作世代與 active 狀態讓替換、登出／帳號切換、離頁及超時後的回應失效；即使傳輸忽略取消，也不得交付。pagehide 清除記憶體結果，pageshow 重新啟用空狀態，不恢復舊檔案。
- 準備以 HTTP、取消及三十秒計時器競速，等待涵蓋回應本文；收到檔案後即結束準備計時，不把圖片或交付時間算入準備上限。逾時先讓操作失效，再通知傳輸取消。
- 回應須成功、內容類型為 text/calendar、非空且有基本完整標記。此檢查不是第二套完整 ICS 解析器；事件內容仍由既有產生器與課程時段 module 負責。
- 登入與資格分別導向既有入口；不自動在登入或付款完成後重送。401 清除當次可重試快照；同帳號未取得檔案的其他準備故障保留快照，供明確重試。
- 已準備 ICS 的交付失敗不清除檔案，後續交付重用完全相同的字串。只在有效新準備完成時自動一般下載一次，重開、重渲染及圖片重試不下載。
- 分享圖片由既有繪製器處理同次課表副本，以操作世代及圖片嘗試區分遲到結果；獨立錯誤與重試不改 ICS。Blob URL 僅供視窗呈現，關閉即釋放，重開從記憶體 Blob 建立新 URL，不重新繪製。

瀏覽器 adapter 負責登入保護的 JSON POST、Blob 下載、Apple 裝置判斷與既有 data URI 交付；內容類型、完整性、等待與狀態由協調 module 管理。Apple 按鈕只在裝置判斷相符時顯示，仍保留一般下載；專用操作不保證原生 App 已接收或完成匯入。

既有 GET／表單入口、帳號匯出資格及零辨識額度可匯出的保障不變。ICS 日期、每週十六次、無明確時區標記及事件識別政策不變；不新增學期、去重、公開連結、雲端保存或永久匯出紀錄。使用者文案只描述已準備或已觸發，不宣稱檔案已保存／事件已加入日曆。
