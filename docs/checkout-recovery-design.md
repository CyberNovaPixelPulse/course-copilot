# 付款返回與付款前課表恢復

規格：GitHub #10；實作票 #11–#16。決策依 ADR 0008 與詞彙表。

## 對外邊界

`createCheckoutRecovery(accountId, dependencies)` 建立單一帳號的協調器，提供 `start`、`handleReturn`、`recheck`、`listDrafts`、`restore`、`discard`、`state` 與 `dispose`。付款建立、確認、離站、儲存與時間為外部依賴。畫面只呈現狀態、取得使用者確認，並套用明確恢復結果。

付款確認不回傳或自動套用課表。`restore` 在目前有課表但未確認時回報 `needs-confirmation`，確認後重新檢查有效期及內容，才回傳完整課表。`dispose` 中止查詢並忽略舊帳號遲到回應。初始權益查詢不得覆蓋已確認付款的新權益；主動恢復亦使尚在執行的辨識畫面回應失效，但不改變伺服器辨識工作或扣次規則。

瀏覽器 adapter 使用既有付款 API，不參與授予額度。Stripe 返回保留付款嘗試識別，取消返回也能找到同次付款；ECPay 建立回應提供付款識別標頭，既有返回訂單號維持不變。帳號歸屬及付款成功仍由已登入後端驗證。Stripe 建立時另在後端保存付款嘗試到 session 的返回關聯（不含課表），取消返回即使略過本機保存也能透過登入後的查詢取得付款識別；此關聯本身不能授予權益。重複嘗試識別不得覆寫既有關聯。

## 保存與隔離

每次付款前以獨立識別保存課表，不使用共用單一鍵，避免新分頁或後次付款覆蓋。版本化記錄依帳號隔離，保存編輯後完整課程、付款方式、付款識別（若已取得）、保存與到期時間。付款嘗試線索不保存課表內容，用於返回帳號預檢及 Stripe 取消返回關聯；不是權益或付款證明。

期限固定七天；付款成功及恢復不刪除或延長。列表、恢復及畫面到期計時都檢查期限，過期內容不提供恢復。使用者可明確捨棄。同一瀏覽器的 localStorage 支援重整與重開，不保證清除瀏覽器資料後恢復，亦不新增跨裝置編輯同步。

單筆損壞記錄不部分載入，不阻斷其他記錄或金流確認。無帳號歸屬的舊 sessionStorage 課表不自動匯入。瀏覽器隔離是應用程式操作與畫面隔離，不將本機儲存當作伺服器授權證據。

## 故障與等待

保存失敗先留頁；使用者重試，或明確確認後略過。建立付款失敗保留備份，不自動建立新付款。取得付款後若保存關聯失敗，保留已取得的付款資料供重試，避免再次建立訂單。

兩種付款都最多自動等待約三十秒；已回報未付款時呈現尚待確認，網路失敗或請求卡住時呈現暫時無法確認。提供手動重查，不自動再次付款。同頁建立付款及同筆查詢各自避免重疊。返回線索留在網址，登入中斷後仍能接續；取消返回不代表交易失敗。
