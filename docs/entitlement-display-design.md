# 瀏覽器帳號權益顯示

規格：GitHub #17，實作票 #18–#23；遵循 ADR 0009 及詞彙表的「帳號權益快照」。

## 對外 interface

`createEntitlementDisplay(accountId, dependencies)` 提供穩定的快照、訂閱、刷新與操作追蹤。正式畫面及測試跨相同 seam；外部依賴為權益讀取及分頁變動通知。每個操作以一次 begin／finish 包含成功與失敗；完整後端結果經集中驗證後原子套用。呼叫端不自行加減額度，不依餘額大小判定版本。

module 維護登入階段及瀏覽器更新次序。操作開始或確認結果讓更早查詢失效；重疊操作結束後重新查詢收斂。普通刷新共用進行中的查詢，變動通知則留下後續補查需求。通知或讀取不會建立付款或辨識工作。

## React 與瀏覽器 adapter

Provider 依登入帳號建立隔離的 module，導覽列及上傳區以同一訂閱取得快照；切換時不需先把舊數字畫出來再清除。付款返回只提供付款確認操作生命週期及後端權益結果，辨識與優惠碼亦依相同契約接入。付款狀態、課表內容及辨識工作仍由原 module 負責。

快照只存在記憶體。分頁透過 BroadcastChannel 傳遞單純變動提示，無法使用時以 storage 變動提示替代；提示不含快照或帳號資料。讀取不廣播，不固定輪詢。回到前景刷新，同時 focus 與 visibility 事件可共用查詢。

權益資料先轉換相容欄位並檢查帳號、數值及分項／總額。允許由兩個明確分項求得舊契約未提供的總額，不把缺少的分項補零；提供總額時必須一致。匯出資格與額度分開，paid 相容欄位不能判定單筆付款成功。

## 故障與登入

暫時故障保留同帳號最後確認結果並標示。沒有成功快照時不顯示假數字。明確未登入則清除快照，使既有操作及回應失效，重新登入後重新載入。舊帳號及舊階段回應不會令新帳號出錯。停止 module 會中止讀取；即使 transport 忽略取消，也不讓等待或舊回應污染新帳號。立即重新連接必須取得新的查詢，舊查詢清理不得清除新查詢的追蹤。補查排隊及進行期間保留數字並標示更新中。

匯出入口即使快照未知也由後端確認資格，不能將未知當成未取得資格而直接提示付款。匯出明確回覆未登入時，同樣先清除共用登入階段再啟動登入。

舊權益開發預覽四項操作及入口已停用，幣別預覽保留。這不是權益政策或後端持久化重構，沒有新增後端 revision；本機次序保護與查詢收斂不等於全域即時排序。
