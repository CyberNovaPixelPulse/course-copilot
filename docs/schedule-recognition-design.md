# 課表辨識 module 設計共識

狀態：Q1–Q15 及完整設計共識已於 2026-10-26 確認，規格已發布至 [GitHub Issue #2](https://github.com/CyberNovaPixelPulse/course-copilot/issues/2)，標記 ready-for-agent。對應 #3–#8 的本機工程實作已加入；#9 真實圖片驗收尚未執行，沒有呼叫實際模型或部署。

## 目標與責任

課表辨識 module 封裝從圖片辨識到可編輯課程的流程，集中模型回應驗證、節次映射、課名整理、時段合併及必要記錄。呼叫端不再學習中間資料與處理順序，以縮小 interface、提高 depth 與 locality。

帳號額度 module 繼續管理辨識工作身分、額度保留、成功結果保存及扣次一致性；課表辨識 module 不另維護這些狀態。沒有可用課程或必要記錄失敗，不構成成功辨識，由帳號額度流程釋放保留。

## 支援範圍與明確修正

- 保留目前模型與辨識提示，以現有行為為整理起點；僅針對已確認項目修正行為。回應驗證契約需落實以下限制，不以修改提示替代確定性檢查。
- 支援目前時間欄右側五個等寬平日欄，以及既有數字 1–15、字母 A–J 節次表；不擴充週末、不等寬欄、圖片鐘點判讀或各校時間表。
- 程式可偵測且無法安全整理的課程異常使整次失敗、不扣次；不得刪除異常課程後用部分結果宣告成功。教室或教師未讀到可留空，不補造資訊。
- 五個星期欄須完整且不重複，欄位、課程清單與節次資料前後一致；不自行移動星期位置。回應內部一致不等於圖片判讀正確。
- 只修正不改變含義的格式差異，例如前後空白、節次字母大寫、數字前導零及課名多餘空白；不猜未知節次、不因相似課名合併。
- 同名課程可集中顯示，每個時段保留自己的教室。不推斷班級或課號。
- 僅合併同套節次表中連續、教室完全相同的同名課程時段；空白教室與已知教室不同，離散節次保留分段，不再依二十分鐘間隔跨表合併。
- 同名課程同日的字母與數字節次重疊時整次失敗，不自動讓字母優先；互不重疊的跨表節次分別保留。
- 同名課程同時段出現不同非空教室時整次失敗；課名、節次與教室完全相同的重複資料去重。不同課程衝堂仍保留供使用者檢查。

## 失敗與記錄

辨識 interface 提供穩定失敗分類與必要資訊，畫面給予具體、可採取行動的提示。課表內容異常、模型暫時故障與必要記錄失敗分開呈現，不直接顯示完整模型回應或內部錯誤，不自動發起第二次模型呼叫。

必要記錄區分模型呼叫完成與課表辨識成功，關聯既有工作，記錄模型、可取得用量、耗時、整理結果及失敗分類；未取得的用量為未知，不假裝為零。本輪不額外保存原始圖片或完整模型回應。

## 測試與驗收

主要測試 seam 是課表辨識 module interface。正式模型 adapter 與固定回應測試 adapter 經過相同的整理與必要記錄流程；驗證外部可觀察的課程或失敗結果，避免將內部函式拆法當作測試契約。

必須涵蓋：

1. 正常五欄、空白星期欄、欄位缺漏／重複與前後不一致。
2. 純格式正規化、未知節次、非法星期、缺少課名或可用時段、可留空的教室／教師。
3. 同套連續節次合併、離散節次分段、不同教室保留及空白教室不被填補。
4. 同名課程跨表重疊拒絕、互不重疊保留、同時段教室衝突拒絕、完全重複去重、不同課程衝堂保留。
5. 模型空回應、格式錯誤、逾時與必要記錄失敗；已發生呼叫的用量及結果如實記錄，未取得用量不記零。
6. 與帳號額度整合：失敗釋放且不扣次，成功結果保存與扣次一致、重試不重複呼叫模型，沿用既有工作恢復保障。

正式切換前，以人工標註的代表性圖片比較課程、星期、節次、教室及拒絕原因，特別檢查嚴格規則是否造成合理圖片被拒絕。素材與實際模型呼叫範圍另行確認；固定回應測試通過不代表真實圖片品質提升。

## 後續工程工作

詳細 interface、穩定錯誤分類、記錄欄位相容方式及檔案配置由後續設計落實，不新增未有實際用途的 adapter。帳號權益政策、工作期限、結果保存期限及付款流程不在本輪重新設計。
