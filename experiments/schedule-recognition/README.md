## 建議首輪範圍（待使用者確認）

原提案最多八張，尚未整批核准。實際已核准並執行的範圍僅為 user-supplied-001 一張、一次，當次額度已用盡；新增圖片或重試需另行確認。後續提案仍為指定圖片每張一次模型呼叫，順序執行，不自動重試、不在故障後補跑或更換樣本。若先遇到模型設定／驗證／供應者故障，停止後續付費呼叫並記錄未執行項目。八次是呼叫數上限，並非金額上限；執行前需確認確切素材清單與呼叫範圍。未確認前只能做本機資料整理及靜態查核。

建議案例清單可由一張涵蓋多項，但不能以少數容易樣本取代困難案例：

1. 正常五個等寬平日欄與數字節次。
2. 中間空白星期欄，右側課程不可左移。
3. 同名、同教室、同套表連續節次（應按既有規則合併）。
4. 同名離散節次（中間空檔不能填補）。
5. 同名不同時段／教室，以及同課不同時段空白教室。
6. 字母與數字節次混合但不重疊（應保留）。
7. 同名跨表重疊或同時段不同非空教室（預期明確拒絕）。
8. 人工可讀但容易混淆的合理圖片，用於發現漏讀、錯讀與錯拒。

素材來源須明列 real 或 synthetic；合成素材只能提供合成場景證據，不能替代真實圖片品質。架構截圖、生成報告截圖及模型中間回應都不是代表性課表素材。

## 人工標註

從 annotation-template.json 複製一份本機清單，填妥圖片路徑、SHA-256、來源、案例標籤、人工讀出的課程／星期／節次／教室，以及預期最後課程或拒絕原因。每張圖片在執行前須由使用者或指定審閱者確認；不得從模型輸出反推答案，再把該輸出當通過依據。

預期成功時，明列可編輯課程的課名、教師（圖片未提供可空）、各時段 weekday、startTime、endTime、location。依 ADR 0007 的節次表獨立核對，不變更辨識規則來讓案例通過。預期拒絕時，明列人工判斷依據與 RecognitionCode；矛盾必須確實存在於圖片，不能僅假定模型會生成矛盾。

模板是格式示例，沒有實際圖片或已核准答案；其空值與人工確認 false 必須阻擋正式執行。標註、素材及實際呼叫授權須分開確認。

## 執行與證據契約

- 走 createScheduleRecognizer 的既有對外介面，使用正式 readScheduleModel adapter；必要記錄改寫入本機實驗證據，不寫產品資料庫、不動帳號額度、不呼叫辨識扣次或付款入口。
- 沿用目前 gpt-4o、temperature 0、top_p 1e-6、seed 42、image detail high、既有提示與嚴格 schema；SDK 自動重試為零，模型等待四十五秒。seed 不代表輸出必然一致。
- 執行前記錄 Git commit、圖片與標註檔 SHA-256、提示／schema 所在 adapter 的內容雜湊，以及上述設定；若程式或素材改變，不能沿用舊驗收結論。
- 每張記錄 UTC 開始／結束時間、實際回報模型、可取得的 token 用量、耗時、可編輯課程或穩定失敗分類，以及人工預期對照；未知用量不能寫成零，不輸出金鑰。
- 不將圖片或完整模型回應寫入產品資料庫，也不默認提交圖片或含個人資料的本機結果至 Git。版本控制保留去識別化的計畫與結果摘要，素材及詳細結果的保存／分享範圍另行確認。

## 判定與停止條件

逐張列出：通過、漏讀、錯讀、錯拒、拒絕原因不符、系統故障、未能判定或未執行。通過只代表該樣本與人工答案相符；同一張可有多種差異，摘要須保留樣本總數與各類問題，不以問題數相加冒充圖片數。

比較課程名稱、星期、節次映射後時間、每時段教室與預期拒絕原因；忽略純排列差異，不能忽略遺失時段、額外時段或錯誤合併。模型失敗或不可讀素材不是內容規則通過，合理圖片遭嚴格檢查拒絕必須列為錯拒或待人工判定。

首輪結果不自動觸發重試、提示修改、規則放寬或正式部署。報告提供完整母體與未執行原因，由使用者評估是否正式切換或另立修正工作；不能只挑成功樣本結案。
